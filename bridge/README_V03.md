# Caveman Focus — HP Bridge v0.3.0

**Founder:** Kiara Lynn Rose Smith's Caveman Focus. **Primary project:** operational automation. This release improves reliability in the existing private GitHub mailbox worker; it is **not** a ChatGPT API, a Windows remote-control tool, or proof the owner HP has connected.

## Changed

1. **Fair queue scanning**. The worker records a SQLite scan cursor and rotates through the whole queue over multiple polls (max 40 fetched requests per poll, max 10 completed/admitted responses per poll). Unsupported, expired, or malformed jobs no longer starve later requests. They remain present for an owner to inspect; they are not silently deleted.
2. **Backwards-compatible SQLite upgrade**. An additional `bridge_meta` table stores the scan cursor without modifying the existing `jobs` or Sidecar database.
3. **Local HTTP loopback integration test** exercises actual `GET`/`PUT` requests through the Python GitHub transport implementation, with a cooperating disposable receiver and no external network.
4. **Windows setup protects existing credentials**. It tests the proposed token and repository privacy first, before replacing saved DPAPI-encrypted credentials. Failed validation preserves the prior configuration.
5. **Optional original Sidecar path** can be configured to enable strictly read-only `domino.py verify` checks.
6. `RUN_HP_BRIDGE_ONCE.bat` now uses the encrypted Windows-user credential saved by setup instead of requiring shell environment variables.

## Install and verify on the HP

- Download or clone the latest CF-0 repository and extract/open it in a permanent folder. Do not extract on top of your original Sidecar data. **There is no database migration of the Sidecar** in this release.
- Double-click `RUN_HP_BRIDGE_DEMO.bat`. This runs a local ping/receipt and all Python tests; it does **not** contact GitHub or establish account access.
- Create a **separate PRIVATE GitHub repository** for the mailbox. The existing `CF-0` repository is public. Do **not** paste token values into ChatGPT, screenshots, issues, or public code. Generate a fine-grained token with only that private repository's Contents read/write permission.
- Double-click `SETUP_HP_BRIDGE_WINDOWS.bat`. Enter the private repository and token in the secure Windows prompts. The setup checks privacy and token before changing local configuration. Optionally supply the absolute original Sidecar folder containing `domino.py`.
- Use `RUN_HP_BRIDGE_ONCE.bat` or `HP_BRIDGE_STATUS.bat` to check the local connection and scheduled-task state. `STOP_HP_BRIDGE_WINDOWS.bat` unregisters scheduling without removing the encrypted credential or ledger.
- Create a single `ping` request in the **private** repo at `bridge/queue/<UUIDv4>.json`, with a body generated by `py -3 bridge\cf_hp_bridge.py make-job`. The owner can do this through a GitHub-connected Work session that has access to the private repository. Confirm that the actual HP produces `bridge/results/<same UUID>.json` and verify its `request_sha256`, status, and `pong` response.
- An automated GitHub message/receipt is **not** automatically a message in this specific ChatGPT chat. A native account integration still needs to be proven.

### Evidence and remaining blockers

- 21 offline Python tests plus a local HTTP transport test pass in the builder environment. Actual HP Windows scheduler installation, encrypted credential storage on that HP, private GitHub round trip, and independent Windows CI of **this new version** remain **unverified until executed**.
- The private mailbox has no authenticated sender policy beyond GitHub repository write permissions, so only trusted principals should have access to it. It only permits `ping` and optionally configured `sidecar_verify`. Received JSON cannot execute shell commands.
- GitHub's Contents API has a directory listing limit of 1,000 entries. The worker fails closed at that limit. A future owner-approved archive/prune mechanism is necessary for sustained workloads; v0.3 does not delete queued requests automatically.
- If power is lost after processing but before the local result is recorded, the worker preserves an uncertain `processing` state instead of blind retrying it. Review those cases rather than treating them as delivered.
- The schedule requires that the Windows user be signed in; it does not keep a powered-off PC active.

### Technical acceptance criterion

The first verified end-to-end result needs: (a) owner-identified HP run, (b) source-labeled private GitHub request, (c) authenticated connection success, (d) matching `request_sha256` and result, (e) repeated poll produces **no duplicate action**, (f) Windows task runs without the interactive console.
