## Working source-level capability

The owner asked for both **hard-coded click/type sequences** and a **Python/GPT reasoning system**, ultimately able to open Google, inspect projects, repair them and use ChatGPT until verified completion. v0.11 adds a reusable first **observe → select → act → verify** browser layer, with deliberate limits.

- `chrome_extension/ui_probe.js`: when the owner clicks **Inspect visible supported controls** in a paired Chrome companion popup, inspect only a finite allowlist of *accessible controls* (not page bodies, user input values, transcripts, private item names, arbitrary links or passwords) from one loaded HTTPS tab: Google search field, exact canonical `https://chatgpt.com/` result, ChatGPT message composer or Drive search field. Max 12 known control labels.
- Desktop `spider_ui_probe.py` and `spider_core.py`: strict host/control/action/index validation, private-RAM snapshot, local paired/ARM gate, clearing on STOP/re-pairing; **Review observed page controls** GUI button. No new host permissions, external data store or persistent remote worker.
- Popup **Focus/click PREVIEWED control** requires a **separate owner confirmation and observed numeric index**. Before action the extension rechecks paired desktop STOP, foreground exact tab and URL, rescans the control and rejects changes/ambiguous controls. The only permitted actions are focus for known search/composer fields (no typing) or clicking an exact canonical ChatGPT homepage link; after a link click the extension requires observed same-tab arrival. The action is single-use, not automatically repeated.
- This does **not** connect page observations directly to GPT autonomous tool choice, does not read a whole screen, click arbitrary buttons, run arbitrary Python or claim an open-ended task is complete. The previous v0.10 bounded 3-turn/2-static-check GPT↔Python loop remains unchanged.
