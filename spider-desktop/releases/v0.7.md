The standalone program now contains `spider_test_runner.py` and a GUI button **Run TRUSTED Python project tests (approval)**. After explicit owner consent on a selected trusted local project, it launches only the fixed Python stdlib unittest discovery command (`python -B -m unittest discover -s tests -p test_*.py -v`) using the current interpreter in that project folder. It records local exit status and test count, rejects zero-test success, limits runtime, supports STOP/best-effort termination and reports failure rather than converting a plan to proof. A passing result can advance an active project repair mission's `verify` step only when the same workspace and mission ID are still selected. Failed and interrupted runs cannot verify a repair.

**Critical authority boundary:** Project tests are executable user code, NOT sandboxed. They inherit local Windows user permissions and can affect files/network. Only the owner may select the project and approve the run, ideally on a disposable copy; the ChatGPT response cannot issue an arbitrary command or approve tests. No automatic GitHub write, new account, remote shell, scheduled work or added Chrome extension permission.
