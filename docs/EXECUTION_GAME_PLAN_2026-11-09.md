## Execution lane and order

### Lane 1 — P0 reliability, start here and continue on the existing hourly executor
1. Choose **one** fresh successful, main-branch watchdog run; validate job step, canonical packet bytes, run attempt and digest with [watchdog readback](../automation_200/watchdog_readback.py).
2. Make the already-existing scheduled CF-200 executor **actually read** that packet before issuing a source-only `accepted_source_only` / `deferred` / `rejected` decision. Identify its actual native provider run ID by authorized provider readback; **never guess or inject an invented run ID into the response**. If unavailable, explicitly mark correlation **unverified** and diagnose the missing adapter rather than generating another summary.
3. Apply [recorded-result correlation checker](../automation_200/watchdog_executor_result.py) to the real, complete provider result. Record exact run IDs/digest and binary pass/fail with privacy-safe provenance. Source tests or a self-authored acknowledgment alone do not pass.
4. **Independent HP acceptance** using only already-approved transport: show a specific *scheduled* Windows invocation, associated wrapper/nonce UUID and digest, and matching durable receipt. Public 32-receipt health totals or a manually initiated ping are not that evidence. If HP evidence is unavailable, pursue another safe P0 task while keeping this gate **OPEN**.
5. Only after a genuine end-to-end run can unattended operation be described as operational; seven-day autonomy requires a separate seven-day test and remains unverified.

**P0 fail/stop conditions:** missing run/attempt; missing or ambiguous source packet; nonexistent native executor result; mismatched digest; stale or truncated completion; owner-local HP auth required; uncertain replay; unsupported control. Stop that attempt, record the exact reason, do **not** manufacture a receipt, and select a safe alternate. Do not rewrite the three-action public HP allowlist, modify schedules, or mark a CF-200 acceptance just for this plan.

### Lane 2 — P1 control clarity / AUTO-08 one-chat acceptance
1. Keep existing Mission Control as the one dashboard. Label controls as **connected + tested**, **source-only**, or **disconnected**. No cosmetic master switch.
2. Run one authorized signed-in account/tab acceptance, keyboard only, no screen-coordinate automation or new tab per conversation. Ensure active chat is eligible and not waiting for human input.
3. Require one completed `continue` response and durable per-chat checkpoint before moving on. Test STOP immediately, then safe resume with no duplicate message. On failure stop without automatic multi-chat retries.
4. After passing, expand to a *small* bounded serial batch, review receipts and costs/usage, then scale cautiously. Cross-account handoffs and physical HP control remain separate permission gates.

**P1 fail/stop conditions:** unknown account, sign-in lost, ambiguous target or submission, rate cap, missing completion signal, failed STOP, unverified checkpoint, unsupported browser capability. Keep the switch disabled and report actual blocker.

### Lane 3 — P2 deadline and real intake (parallel, not competing with P0)
1. **By November 13, 2026, if eligible:** resolve the published Bridge Builders Community Microgrant's individual-applicant category discrepancy, venue feasibility, and only true applicant declarations. Make a submission decision before deadline. **Never select a false category or claim an unbooked venue.** Existing reply watch remains enabled; grant confirmation is not award/payment.
2. Finish the **existing** private no-login Clarity Brief Google Form; correct required scope/privacy acknowledgment, email validation, optional public reference and confirmation. Test with a logged-out respondent. **Only then** put its safe respondent URL on the $15 public page. Do not publish its editor link or any private response.
3. Keep the free Clarity Card as the front door; make a real $5/$15 manual customer inquiry → qualification → offer acceptance → delivery → separately verified payment sequence. Do not convert a voluntary donation into a purchase or invent social proof.
4. Record verified financial results privately, publish only approved non-sensitive aggregates. If the grant is blocked, promptly pivot to legitimate customer intake without submitting misrepresentations or paying for new subscriptions.

**P2 fail/stop conditions:** unresolved eligibility, no grant permission, untested anonymous form, no real customer, no independently verified payment. Record `not submitted`, `inquiry only`, or `income not verified` accurately.
